# 내셔널짐 전자계약서 — 도입 기획서

> **목적** 직원 파일럿(시뮬레이션)을 거쳐 전 지점 본 도입까지 무리 없이 전환
> **작성 기준** 시스템 v2 Enterprise · 2026-06-03
> **대상** 대표 · 지점 매니저 · 데스크 직원

---

## 0. 한 장 요약

```
[Phase 0] 사전 준비        →  [Phase 1] 직원 파일럿     →  [Phase 2] 본 도입
 (반나절)                     (2~3일)                      (상시)
 · 스키마 재실행               · 직원끼리 실제 시연          · 신규/재계약 전자 전환
 · 관리자 계정                · 4가지 시나리오 통과         · 회원 안내 멘트 적용
 · 테스트 1건                 · 합격 기준 체크             · 첫 주 매일 모니터링
```

**원칙 3가지**
1. **직원이 먼저 회원이 되어본다** — 직원이 직접 링크 받아 동의까지 해봐야 회원에게 설명할 수 있다.
2. **실패 케이스를 일부러 만들어본다** — 본인확인 실패·만료를 미리 겪어야 당황하지 않는다.
3. **회원에게는 "더 편해졌다"로 전달한다** — "법적 절차"가 아니라 "1분이면 끝나는 간편 서명"으로.

## 1. Phase 0 — 사전 준비 (운영 시작 전 반드시)

데모와 별개로, **실제 작동**하려면 아래가 끝나야 합니다.

| # | 할 일 | 담당 | 확인 방법 |
|---|---|---|---|
| 0-1 | Supabase SQL Editor 에서 `supabase_schema.sql` **재실행** | 시스템 관리자 | 에러 없이 "Success" |
| 0-2 | 활성 약관 확인 | 시스템 관리자 | 아래 쿼리 결과 3건 `is_active=true` |
| 0-3 | 관리자 계정 발급 (지점별 or 공용) | 시스템 관리자 | admin.html 로그인 성공 |
| 0-4 | **테스트 계약 1건** 본인 핸드폰으로 발송 | 매니저 | 본인확인→동의→PDF까지 완료 |
| 0-5 | 직원에게 매뉴얼·시연 링크 공유 | 매니저 | manual.html / demo.html 전달 |

```sql
-- 0-2 확인용
select contract_type, version, is_active
from contract_templates
where is_active = true
order by contract_type;
-- combo / pt / golf 각 2026-05-19 가 active 면 정상
```

> ⚠️ **0-1을 건너뛰면** 회원이 마지막 제출에서 `digest 함수` 오류가 납니다. (이전에 수정한 부분) 반드시 재실행.

## 2. Phase 1 — 직원 파일럿 (시뮬레이션) ★ 가장 중요

### 2-1. 목적

- 직원이 **회원 입장**을 직접 체험 → 응대력 확보
- 실제 기기·네트워크에서 **버그·불편 발견**
- 실패 상황 대응 **연습**
- 도입 가능 여부 **최종 판단**

### 2-2. 준비물

- 직원 본인 스마트폰 (각자)
- 데스크 PC 또는 태블릿 (admin 발송용)
- 관리자 로그인 계정
- 시간: 1인당 약 15분, 전체 1~2시간

### 2-3. 진행 방식 — 2인 1조 롤플레이

> 한 명은 **직원 역할**(발송), 다른 한 명은 **회원 역할**(수신·동의). 그다음 역할을 바꿔 반복.

#### ▶ 시나리오 A — 정상 계약 (필수)

1. 직원 역할: admin.html 로그인 → 약관·지점 선택
2. 회원 역할의 **실제 이름·생년월일·본인 폰번호** 입력 (가상 항목: "PT 10회 / 30만원")
3. 링크 생성 → 카톡 메시지 복사 → 회원 역할에게 카톡 발송
4. 회원 역할: 자기 폰에서 링크 클릭 → 본인확인 → 약관 끝까지 스크롤 → 동의 → 제출
5. 직원 역할: list.html 에서 '동의완료' 뜨는지 확인 → view.html 에서 PDF 저장

✅ **확인:** 5단계가 막힘 없이 흐르는가? PDF가 제대로 나오는가?

#### ▶ 시나리오 B — 본인확인 실패 → 재발송 (필수)

1. 일부러 **생년월일을 틀리게** 입력해서 발송
2. 회원 역할: 본인확인에서 "정보 불일치" 뜨는 것 확인
3. 직원 역할: list.html 에서 발송 정보 확인 → 올바르게 **새 링크 재발송**
4. 회원 역할: 새 링크로 정상 통과

✅ **확인:** 실패 메시지가 명확한가? 직원이 재발송 흐름을 아는가?

#### ▶ 시나리오 C — 약관 안 내리고 동의 시도 (필수)

1. 회원 역할: 약관을 **중간까지만** 스크롤하고 동의 버튼 누르려 시도
2. 버튼이 **비활성**인 것 확인 → 끝까지 내리면 활성화되는 것 확인

✅ **확인:** "끝까지 봐야 한다"를 회원에게 안내할 수 있는가?

#### ▶ 시나리오 D — 환불 문의 응대 롤플레이 (권장)

1. 회원 역할이 "환불 어떻게 돼요?" 질문
2. 직원 역할이 매뉴얼 Part 6 환불 멘트로 응대
3. "동의 안 했다" 주장 → view.html 에서 동의 시각·항목 보여주기 연습

✅ **확인:** 직원이 환불 공식과 증거 제시 방법을 아는가?

### 2-4. 파일럿 합격 기준 (체크리스트)

모든 직원이 아래를 **혼자서** 할 수 있어야 본 도입:

- [ ] admin 로그인 → 계약 발송 → 카톡 메시지 복사까지 막힘없이
- [ ] 생년월일 필수 입력을 빠뜨리지 않음
- [ ] 지점을 정확히 선택함
- [ ] 회원 본인확인 실패 시 재발송할 수 있음
- [ ] list.html 에서 상태 확인 가능
- [ ] view.html 에서 PDF 저장 가능
- [ ] "약관 끝까지 내려야 동의된다" 안내 가능
- [ ] 환불·양도 기본 멘트 가능

### 2-5. 피드백 수집 (파일럿 후 5분 설문)

직원에게 물어볼 것:
1. 어느 단계가 가장 헷갈렸나?
2. 회원이 막힐 것 같은 지점은?
3. 발송 화면에서 불편한 점?
4. 추가로 있으면 하는 기능?

→ 수집된 내용은 시스템 관리자에게 전달, 도입 전 보완 가능 여부 검토.

## 3. Phase 2 — 본 도입

### 3-1. 적용 범위

- **시작일부터 신규 등록 + 재계약 전부** 전자계약으로
- 기존 종이 계약은 그대로 유효 (법정 보존기간 보관)
- 예외: 회원이 끝까지 거부 시 → 종이 병행 (단, 사유 기록)

### 3-2. 도입 첫 주 운영 수칙

- 매일 영업 종료 후 list.html 에서 **미완료 건** 확인 → D-day 임박 건 재안내
- 첫 주는 발송 시 직원이 회원 옆에서 **첫 화면까지 같이** 봐주기 (안내 멘트 + 약관 스크롤 강조)
- 문제 발생 즉시 매니저 → 시스템 관리자 보고 채널 유지

### 3-3. 모니터링 지표 (KPI 카드 활용)

| 지표 | 목표 | 확인 위치 |
|---|---|---|
| 발송 대비 동의완료율 | 90%+ | list.html KPI |
| 평균 완료 소요시간 | 10분 이내 | view.html 감사로그 |
| 본인확인 실패 재발송 | 점차 감소 | list.html |
| 만료(미완료) 건 | 5% 이하 | KPI '만료' 카드 |

## 4. 회원 안내 멘트 (채널별 · 복사해서 사용)

> 핵심 톤: **"종이 → 더 간편하고 안전한 모바일 서명으로 바뀝니다"**
> 절대 "법적으로 필요해서"라고 딱딱하게 말하지 말 것.

### 4-1. 대면 (데스크/상담 중) — 가장 많이 씀

> "회원님, 저희가 이번에 계약서를 **모바일 전자서명**으로 바꿨어요.
> 종이에 쓰실 필요 없이, **카카오톡으로 보내드리는 링크**에서 약관 확인하고
> 동의 체크만 하시면 1분이면 끝나요. 계약서도 PDF로 바로 받으실 수 있고,
> 분실 걱정도 없어요. 지금 바로 보내드릴게요!"

### 4-2. 재계약 회원에게 (전자 전환 첫 안내)

> "이번 재계약부터는 종이 대신 **휴대폰으로 간편하게** 진행됩니다.
> 카톡으로 링크 하나 보내드릴 텐데, 본인확인하고 약관 보신 다음
> 동의만 눌러주시면 돼요. 어렵지 않으세요, 제가 옆에서 도와드릴게요."

### 4-3. 카카오톡 사전 공지 (단체/개별 발송용)

```
[내셔널짐] 전자계약서 도입 안내 📱

안녕하세요, 내셔널짐입니다.
앞으로 PT·골프 (재)계약을 종이 대신
모바일 전자계약으로 진행합니다.

✅ 카톡 링크에서 약관 확인 → 동의 체크 → 끝 (1분)
✅ 계약서 PDF 즉시 발급, 분실 걱정 없음
✅ 「전자서명법」에 따라 종이와 동일한 효력

다음 계약 때 링크를 보내드리겠습니다.
편하게 진행하시면 됩니다 😊
문의: (지점 연락처)
```

### 4-4. 전화 응대

> "네 회원님, 이제 계약서는 카카오톡으로 보내드려요.
> 링크 누르시고 성함·생년월일·전화 뒷자리만 확인하시면
> 약관 보시고 동의 체크로 끝나세요. 종이보다 훨씬 빨라요.
> 지금 발송해드릴까요?"

### 4-5. 거부감·불안 있는 회원

> "걱정 안 하셔도 돼요. 모두싸인·도큐사인처럼 큰 회사들도 다 쓰는 방식이고,
> 법적으로 종이 서명이랑 똑같은 효력이에요. 오히려 기록이 더 정확하게 남아서
> 회원님께도 안전합니다. 혹시 어려우시면 제가 화면 보면서 같이 해드릴게요."

(그래도 끝까지 거부 시)
> "네, 그럼 이번엔 종이로 도와드릴게요. 다음에 한번 편하게 써보세요."
> → 종이 병행하되 사유 기록

### 4-6. "왜 생년월일까지 넣어요?" (불신)

> "본인 확인용이에요. 다른 사람이 회원님 명의로 계약 못 하게 막는 거라,
> 오히려 회원님을 보호하는 장치예요. 카톡 메시지에 안내도 같이 가요."

## 8. 리스크 & 대응

| 리스크 | 대응 |
|---|---|
| 고령 회원이 어려워함 | 직원이 옆에서 화면 보며 도움 (입력은 회원 본인) |
| 회원 폰 데이터/카톡 없음 | 데스크 wifi 안내, 공용 태블릿 대여 |
| 본인확인 반복 실패 | 발송 정보 재확인 → 재발송 (가장 흔한 원인은 직원 입력 오류) |
| 회원 거부 | 종이 병행 (사유 기록), 다음 기회에 재안내 |
| 시스템 오류 | "확인 후 연락" 안내, 추측 답변 금지, 매니저 보고 |
| 직원이 대신 입력 유혹 | **절대 금지** 교육 — 효력 무효·분쟁 시 불리 |
